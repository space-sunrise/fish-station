# Исследование и перенос достижений SS13

Этот документ фиксирует проверяемые результаты аудита систем достижений SS13 и решения по их нативной адаптации для Fish Station на архитектуре SS14/Sunrise.

## Методика

1. Исследовать несколько активных и исторических форков SS13.
2. Зафиксировать источник, версию и точное условие каждого достижения.
3. Свести совпадающие достижения без потери происхождения.
4. Сопоставить условия с реально существующими событиями и системами SS14.
5. Исключать или адаптировать недоступные механики с обязательным обоснованием.
6. Реализовывать контент только после аудита архитектуры, persistence и UI текущего проекта.

## Формат каталога

| Поле | Значение |
| --- | --- |
| ID | Стабильный идентификатор достижения в Fish Station |
| Название | Оригинальное или адаптированное название |
| Описание | Локализуемое описание |
| Источник | Проект SS13, commit или версия и путь |
| Условие | Проверенное условие получения |
| Категория | Категория контента |
| Сложность | Оценка сложности с пометкой источника или характера оценки |
| Прогресс | Бинарное состояние либо измеряемый прогресс |
| Секретное | Правила видимости до получения |
| Интеграция SS14 | События и системы, необходимые для серверной проверки |
| Решение | Перенос, адаптация, объединение или исключение |
| Статус | Состояние реализации и проверки |

## Аудит Fish/SS14

Готовой системы достижений в проекте нет. Для реализации выбраны существующие инфраструктурные решения:

- `UserDbDataManager` и `PlayTimeTrackingManager` как образец lifecycle account data;
- `IServerDbManager` и partial-расширения `ServerDbBase` для persistence;
- `RoadmapLikesSystem` как образец типизированной server/client синхронизации;
- общий `UIController` и одно окно для Lobby и ESC;
- существующие popup/chat notification API;
- YAML-прототипы и FTL-локализация.

Подробные решения и список минимальных core-hooks находятся в `AchievementsArchitecture.md`.
